The tension

The demo is the easy ten percent.

A prototype proves something can work. A deployment proves it works every week, owned by someone, with a way back when it breaks.

× THE PROTOTYPE

Impressive once

A prompt that wowed the meeting. No evals, no owner, no version number. When it drifts, nobody notices until a customer does.

✓ THE SYSTEM

Boring on purpose

The same prompt with an eval gate, a version history, usage telemetry, and a retirement date. It breaks loudly and gets fixed fast.

The rule: a prototype earns production only after it survives an eval set, a named owner, and a rollback plan.
The machine

Deployment is a loop, not a launch.

Sketched as an n8n workflow: gate it, version it, watch it, retire it.

LOOP 01

The eval gate

Every prompt version runs a fixed test set before it ships. Drift gets caught at the gate, never in production.

In practiceA Slack alert to the owner with the failing cases attached, before the version goes live.
LOOP 02

Version control

Prompts, models, and data get version numbers like code. A bad deploy rolls back in one click.

In practiceA ClickUp task auto-filed on every deploy with the prompt diff.
LOOP 03

Adoption telemetry

Track who uses it, how often, and who stopped. An unused tool is a liability, not an asset.

In practiceA weekly digest to the channel: usage up, flat, or gone quiet.
LOOP 04

The retirement ritual

Sunset what nobody uses. Archive the learning so the next prototype starts smarter.

In practiceA quarterly retire review. No funerals, just archive notes.
